## Завдання 1. Найменше значення у двійковому дереві пошуку

`find_min(root)` іде від кореня лівими гілками, поки є лівий нащадок. У двійковому дереві пошуку ліворуч від вузла зберігаються менші значення, тому крайній лівий вузол містить мінімум. Для порожнього дерева функція повертає `None`.

Час роботи становить `O(h)`, де `h` — висота дерева. Додаткова пам’ять становить `O(1)`.

## Завдання 2. Сума всіх значень у двійковому дереві пошуку

`sum_values(root)` обходить дерево в глибину за допомогою стека й додає значення кожного вузла. Повторювані значення зберігаються в окремих вузлах і також входять до суми. Для порожнього дерева результат дорівнює `0`.

Час роботи становить `O(n)`, де `n` — кількість вузлів. Стек займає `O(h)` додаткової пам’яті.

У прикладі для завдань 1 і 2 дерево побудоване зі значень `[8, 3, 10, 1, 6, 14, 4, 7, 13]`. Мінімум дорівнює `1`, сума — `66`. Обидва скрипти використовують спільну реалізацію дерева з `bst.py`. Для вставлення використано схему спуску від кореня з розділу про двійкові дерева пошуку. [Robert Sedgewick і Kevin Wayne, *Algorithms*, реалізація `BST`](https://raw.githubusercontent.com/kevin-wayne/algs4/master/src/main/java/edu/princeton/cs/algs4/BST.java)

## Завдання 3. З’єднання кабелів

`min_connection_cost(lengths)` будує мінімальну купу за допомогою `heapq`. На кожному кроці функція дістає два найкоротші кабелі, додає їхню сумарну довжину до витрат і повертає об’єднаний кабель у купу. Функція повертає мінімальну суму витрат і список кроків у порядку виконання. Для нуля або одного кабелю результатом є `(0, [])`. [Документація Python для `heapq`](https://docs.python.org/3.12/library/heapq.html)

Оптимальність можна пояснити через дерево з’єднань. Кожна початкова довжина входить у загальну суму стільки разів, скільки з’єднань відділяють кабель від кореня. У найглибшій парі листків зі спільним батьком можна розмістити два найкоротші кабелі. Обмін із довшими кабелями в цій парі не збільшує загальних витрат. Після з’єднання пари задача зводиться до тієї самої задачі з одним кабелем менше.

Для довжин `[4, 3, 2, 6]` порядок з’єднань такий.

1. `2 + 3 = 5`
2. `4 + 5 = 9`
3. `6 + 9 = 15`

Мінімальні загальні витрати становлять `5 + 9 + 15 = 29`. Час роботи становить `O(n log n)`, де `n` — кількість початкових кабелів. Купа та список кроків займають `O(n)` додаткової пам’яті.
